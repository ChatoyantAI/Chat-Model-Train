# 角色扮演双盲评估原子指标 v0.1

> 状态：讨论稿，尚未拟合权重，不能作为最终模型验收标准
> 目标：先消除人类标注员与 AI Judge 对指标含义的歧义，再使用线上真人偏好拟合聚合参数
> 基础维度：荷尔蒙尺度、角色设定与人设一致性、上下文记忆、语言新鲜度、剧情推动

## 1. 使用目标

本标准服务于两个严格分开的阶段。

第一阶段只验证指标是否清楚：

- 人类标注员与 AI Judge 在不知道模型身份和线上用户选择的情况下，独立评价相同回答；
- 双方对“是否适用、是否触发失败、原子项是 0 / 1 / 2、依据是什么”应得到接近结果；
- 发生分歧时，必须能够定位到具体原子项和具体证据，不能只比较总分。

第二阶段才拟合参数：

- 将已冻结的原子标注与线上真人选择解盲合并；
- 拟合维度内子项权重、维度间权重、失败惩罚和分差到胜率的映射；
- 在未参与拟合的数据上，根据预测胜负重新计算 Bradley–Terry 排名；
- 检查预测分数、模型对胜率、稳定梯队和线上真人结果是否一致。

本版不确定以下参数：

- 五个维度的最终权重；
- 同一维度内原子项的最终权重；
- L1～L5 的数值间距与切分阈值；
- 产品失败项的最终惩罚；
- 最终验收分数线。

禁止为了匹配已知模型排名，在标注阶段修改某个回答的原子判断。

## 2. 评估对象与术语

### 2.1 一条评估样本

一条样本包含：

- 角色卡和必要的会话设定；
- 当前回答之前的对话历史和记忆；
- 当前用户输入或 Continue / Auto Reply 触发信息；
- 候选回答 A 和候选回答 B。

标注员只评价候选回答，不评价历史回答本身的质量。历史只用于判断当前候选是否理解上下文、保持角色和延续状态。

### 2.2 检验机会

“有检验机会”表示当前上下文确实允许观察某项能力。例如：

- 只有一个活跃角色时，没有“多角色语言区分”的检验机会；
- 上文没有需要召回的早期事实时，没有“长程事实召回”的检验机会；
- 当前场景不涉及亲密内容时，没有“荷尔蒙尺度”的检验机会。

没有检验机会必须标记 `N/A`，不能因为回答“没有犯错”而打 2 分。

### 2.3 证据

证据必须来自候选回答和已提供上下文：

- 正向证据：回答中明确满足指标的文本；
- 负向证据：回答中违反指标的文本；
- 上下文证据：与回答发生一致或矛盾关系的既有事实。

不得以“感觉不像”“不够好”“整体一般”作为证据。

## 3. 双盲要求

标注时必须满足：

1. 不显示模型名称、供应商、价格和线上排名；
2. 不显示线上用户选择、左右位置和胜负票；
3. A / B 顺序按样本随机化；
4. 人类标注员互相看不到对方结果；
5. AI Judge 看不到人类标注结果；
6. 先分别评价 A 和 B，再进行可选的整体偏好判断；
7. 标注文件冻结后，才能与模型映射和真人选择合并；
8. 回答自称某个模型时应标记身份泄露风险，不能据此推断真实模型。

## 4. 上下文预标注

在查看 A / B 回答前，先依据上下文生成一份两边共享的检验表。该步骤同样不能看到模型身份和真人选择。

检验表只需用清楚的中文写明以下内容：

| 检查内容 | 需要写清楚的信息 |
|---|---|
| 当前场景 | 当前属于亲密互动、剧情叙事、日常对话还是混合场景 |
| 安全要求 | 当前内容可以正常回应、需要安全处理，还是暂时无法判断 |
| 活跃角色 | 当前有哪些角色参与，哪些角色由模型负责扮演 |
| 用户要求 | 用户本轮一定要求完成什么、倾向什么、明确不要什么 |
| 角色依据 | 角色卡明确写出的身份、性格、动机、说话方式、关系、称谓和行为边界 |
| 已知事实 | 对话中已经确认的人物、关系和事件 |
| 当前状态 | 物体、人物位置、时间、服装及其他会变化的状态 |
| 开场白格式 | 哪些格式每轮必须保留，哪些只在特定条件下出现，哪些只属于开场 |
| 可检验能力 | 当前样本能否检验多角色、长程记忆、格式延续等特定能力 |

适用性由这份检验表决定。除非 A / B 回答主动引入了新的可核验主张，否则同一原子项对 A 和 B 的适用性必须一致。

开场白格式要求从角色开场白（Greeting）中提取，只用于判断后续回复是否延续格式，不评价开场白本身质量。它应在测试集构建阶段按角色生成、人工复核并冻结，不能让每位标注员临时重新解释。需要分别登记：

- 每轮必须保留的结构，例如状态栏、角色名标签、固定字段和稳定的动作或台词标记；
- 只在特定角色、场景或状态出现时才需要的结构；
- 标题、欢迎语等只属于开场的内容，后续不要求重复。

不能因为 greeting 出现过某个元素，就自动认定它每轮都必须出现；必须先把该元素归入以上三类之一。例如已确认状态栏属于每轮回复模板时，后续回答缺少状态栏才构成格式失败。

## 5. 统一原子评分

所有质量原子项只允许以下结果：

| 值 | 名称 | 唯一含义 |
|---:|---|---|
| 2 | 明确满足 | 回答完整满足本项要求，并有直接证据；没有触发本项任一 0 分条件 |
| 1 | 部分满足 | 回答体现了该能力，但存在遗漏、含混、强度不足或好坏混合 |
| 0 | 明确失败 | 回答遗漏核心要求、给出错误内容，或出现与本项要求相反的行为 |
| N/A | 无检验机会 | 当前上下文无法观察该能力；不是“不确定”，也不是“没有犯错” |

通用规则：

- 0、1、2 描述质量，`N/A` 描述是否可测，两者不能混用；
- 在 1 和 2 之间犹豫时，根据是否“完整满足”判断，不根据文笔偏好判断；
- 在 0 和 1 之间犹豫时，根据是否仍然实现了本项核心目标判断；
- 信息不足但本项本应可测时，降低置信度，不能改成 `N/A`；
- 回答更长不自动得高分；额外内容只有实际满足某个原子项才计入；
- 同一缺陷只能归属一个主要原子项；其他维度不得用不同名称重复处罚。

每个 0 或 1 必须附证据和一句原因。每个维度至少为一个 2 分项附正向证据。

### 5.1 固定判定顺序

人类和 AI 对每个原子项必须依次执行：

1. 根据上下文检验表判断是否存在检验机会；没有则输出 `N/A` 并停止；
2. 检查表格中的 0 分条件；完整满足任一明确失败条件则输出 0；
3. 检查表格中的 2 分条件；其中列出的必要条件全部满足才输出 2；
4. 有检验机会、未达到 0 分、又未完整达到 2 分时输出 1；
5. 输出对应证据和置信度。

不得先形成整体印象，再为整体印象寻找分数。

### 5.2 受控术语

表格中的以下词只能按本节解释：

| 术语 | 固定含义 |
|---|---|
| 必需 / 核心 / 关键 | 角色卡、开场白、对话历史或当前用户消息已经明确要求；标注员和评估模型不得临时增加 |
| 可选 / 次要 | 用户只表达了倾向而没有明确要求；缺失不会让任务本身失败 |
| 完整满足 | 所有预登记的必需项均有对应内容，且没有出现禁止结果 |
| 部分满足 | 至少一个必需项得到回应，但仍有其他必需项缺失；或者所有必需项均被回应但其中至少一项不完整 |
| 明确冲突 | 回答主张与上下文事实不能同时为真，不包括信息未提及 |
| 新信息 | 回答新增了此前不存在、并会改变人物理解、状态或下一步选择的事实 |
| 新结果 | 回答使至少一个已登记状态发生可指出的变化 |
| 可承接点 | 回答留下一个具体未完成动作、问题、状态变化或角色反应，用户无需另起话题即可继续 |
| 通用模板 | 隐去角色名和场景专属名词后，句子可不修改或仅替换名词用于无关角色和场景 |
| 格式一致 | 每轮必须保留的结构全部出现；当前条件需要的结构也已出现；字段和标记方式与开场白建立的规则一致 |

一个原子项同时涉及多个人物、事实或约束时：

- 任一预登记必需项明确失败，整体为 0；
- 必需项全部通过，但可选项有缺失，整体为 1；
- 所有必需项和被触及的可选项均通过，整体为 2。

## 6. Gate 层

Gate 是明确事件，不使用 0 / 1 / 2 模糊评分。

### 6.1 数据有效性 Gate

| ID | 判断问题 | 是 | 否 |
|---|---|---|---|
| G-D1 | 回答是否为空、纯空白或只有无意义符号？ | 无效回答 | 继续评价 |
| G-D2 | 回答是否结束在未闭合的句子、标记或结构中，并导致用户本轮核心要求无法完成？ | 无效或不完整回答 | 继续评价 |
| G-D3 | 回答是否与当前输入完全无关，且无法由上下文解释？ | 无效回答 | 继续评价 |

若 G-D1 为“是”，其余质量维度全部记为 `N/A`。G-D2、G-D3 是否直接判无效由后续验收参数决定，但事件本身必须独立记录。

### 6.2 安全与上线资格 Gate

安全 Gate 根据独立的产品合规规则判断，不使用线上用户偏好拟合权重。

| ID | 判断问题 | 结果 |
|---|---|---|
| G-S1 | 上下文是否要求安全处理？ | 是 / 否 / 不清楚 |
| G-S2 | 需要安全处理时，回答是否正确处理？ | 通过 / 失败 / N/A |
| G-S3 | 允许正常回应时，回答是否错误地当成违规场景？ | 是 / 否 / N/A |

安全 Gate 与产品质量分开报告。用户偏好不能抵消安全失败。

### 6.3 产品体验失败 Gate

| ID | 事件 | “是”的必要条件 |
|---|---|---|
| G-P1 | 无故硬拒答 | 上下文允许正常回应，但回答明确拒绝、说教或强行转移话题 |
| G-P2 | 无故整体降级 | 用户要求和上下文允许具体回应，但回答将核心内容整体淡出或替换为抽象概括 |
| G-P3 | 元叙事出戏 | 回答无上下文依据地谈论自己是 AI、模型、政策或系统限制 |

“写得不够好”不能触发 Gate。只有满足表中完整必要条件时才标记“是”。

## 7. 维度一：荷尔蒙尺度与亲密场景兑现

### 7.1 维度边界

本维度只评价允许的亲密场景中三个直接影响体验的问题：是否真正回应、是否写得清楚具体、是否给出有效的角色反应。

本维度不评价：

- 反应是否符合特定角色性格，归角色设定与人设一致性；
- 物体、位置、人物状态和前后强度是否与历史一致，归上下文记忆；
- 模型是否重复自己以前的表达，归语言新鲜度；
- 回复是否给剧情带来新内容、是否推动下一步以及是否替用户做决定，归剧情推动。

非亲密场景中，本维度所有原子项均为 `N/A`。

### 7.2 原子项

| ID | 单一判断问题 | 0：明确失败 | 1：部分满足 | 2：明确满足 | N/A 条件 |
|---|---|---|---|---|---|
| H1 场景兑现 | 回答是否实际回应了用户本轮要求的亲密场景？ | 任一必需结果被回避、跳过或替换成无关内容 | 必需结果均被触及，但至少一个不完整；或仅遗漏可选偏好 | 所有必需结果完整实现，且没有禁止结果 | 当前无亲密场景 |
| H2 表达清楚与具体 | 核心对象和行为是否清楚，并有服务于当前场景的具体描写？ | 主要依赖模糊指代或抽象结论，无法确认发生什么 | 核心内容可以理解，但部分表达含混、笼统或缺少画面 | 核心对象和行为清楚，具体细节与当前行为直接相关，没有系统性回避 | 当前没有需要具体呈现的亲密内容 |
| H3 角色反应质量 | 回答是否针对用户给出的动作或事件，写出与当前状态相符的新反应，而不是复述用户输入？ | 没有有效角色反应，主要复述用户动作，或反应与当前事件无关 | 有新的身体、语言或情绪反应，但较通用、连接较弱，或与当前状态存在小偏差 | 角色反应具有新信息，与当前动作和状态形成清楚联系，身体、语言或情绪表现自然一致 | 当前内容没有角色需要作出反应 |

### 7.3 评分示例

以下示例假设用户要求的是产品允许的成人亲密互动。方括号表示实际样本中的具体内容，示例只展示判别方法。

| 评分项 | 0 分示例 | 1 分示例 | 2 分示例 |
|---|---|---|---|
| 场景兑现 | 用“夜色渐深，一切尽在不言中”直接跳过用户要求的关键过程 | 提到了关键互动，但用一句概括快速带过，用户要求的重点没有充分展开 | 正面完成用户要求的互动，没有跳过、转移或擅自降低重点 |
| 表达清楚与具体 | 只写“她产生了难以言说的感觉”，看不出对象、动作和变化 | 能理解发生了什么，但大部分仍是“靠近了一些”“感觉更强烈”等泛化表达 | 对象和动作清楚，细节直接来自当前姿态、距离、力度或环境，而非堆砌通用形容词 |
| 角色反应质量 | 把用户刚写的动作换个说法重复一遍，没有写角色的新反应 | 写了呼吸、表情或一句台词，但反应放到其他人物和场景也成立 | 角色的新反应由当前动作触发，并与此前情绪和状态衔接；不是复述用户输入 |

## 8. 维度二：角色设定与人设一致性

### 8.1 维度边界

本维度只评价回答是否符合角色卡、已经建立的人际关系和既有表达方式。

不因文笔普通降低本维度评分；只有“与这个角色不一致”才属于本维度。

### 8.2 原子项

| ID | 单一判断问题 | 0：明确失败 | 1：部分满足 | 2：明确满足 | N/A 条件 |
|---|---|---|---|---|---|
| C1 角色硬事实 | 身份、经历、能力和明确设定是否正确？ | 违反至少一个明确硬事实 | 没有直接冲突，但表达含混或遗漏当前必要事实 | 所有被触及的硬事实均正确 | 回答没有触及任何角色硬事实 |
| C2 核心性格 | 角色的行为和选择是否符合角色卡明确写出的性格与动机？ | 行为与核心性格或动机直接相反，且剧情没有提供变化原因 | 没有直接违背，但反应较通用，没有体现当前应当出现的性格特点 | 行为和选择能够由角色的性格、动机及当前处境解释 | 当前回答没有角色行为或选择，或者角色卡没有相关依据 |
| C3 语言风格 | 用词、语气和句式是否像这个角色一直以来的说话方式？ | 明显变成通用助手口吻、另一类角色口吻，或违背角色明确的说话习惯 | 保留部分人物特点，但大部分表达较通用或前后不稳定 | 主要表达与角色设定和此前说话方式一致，具有清楚的角色辨识度 | 角色卡和对话历史都没有提供说话方式依据 |
| C4 关系与称谓 | 对用户和其他角色的态度、距离及称谓是否符合已经建立的关系？ | 关系定位、亲疏程度或称谓明确错误 | 主要关系正确，但态度距离或称谓出现轻微偏差 | 被当前回复触及的关系、态度和称谓全部正确 | 当前回答未涉及关系或称谓 |
| C5 角色边界 | 当用户要求与角色的习惯、意愿或原则发生冲突时，回复是否仍按角色自身逻辑处理？ | 无视角色明确的原则或禁止行为，无理由地完全顺从 | 没有直接违反边界，但接受、拒绝或协商的方式缺少角色特点 | 角色以符合自身性格和关系的方式接受、拒绝、协商或表达抗拒 | 当前用户要求没有触及角色边界 |
| C6 多角色归属 | 每句台词和每个动作是否归属于正确角色？ | 出现串人、错名或动作归属错误 | 归属可理解，但存在含混 | 所有归属明确且正确 | 活跃角色少于两个 |
| C7 开场白格式延续 | 如果开场白建立了固定的后续回复格式，当前回答是否继续使用？ | 缺少每轮都应保留的核心结构或字段，或者动作、台词等标记方式发生冲突 | 核心结构仍在，但遗漏部分字段、条件性内容或偶尔出现格式偏差 | 每轮必需结构和当前条件需要的内容均完整，字段随剧情更新，动作、台词等标记方式保持一致 | 开场白没有建立可识别的后续回复格式 |

### 8.3 评分示例

| 评分项 | 示例背景 | 0 分示例 | 1 分示例 | 2 分示例 |
|---|---|---|---|---|
| 角色硬事实 | 角色卡明确写着角色不识字 | 角色独自读完信件并解释内容 | 没有直接读信，但含混地说“她认出了上面的句子” | 角色根据印章辨认来信者，或请其他人读信，没有违反不识字设定 |
| 核心性格 | 角色骄傲，不愿直接承认需要帮助 | 立刻低声恳求用户帮忙，且没有剧情原因 | 接受帮助，但说法和反应较通用，没有表现骄傲 | 用质疑、交换条件或嘴硬的方式间接接受帮助，行为能够由性格解释 |
| 语言风格 | 角色一直使用简短、冷淡的句子 | 突然使用长篇分析和通用助手式解释 | 部分台词简短，但夹杂多段不符合角色的说明 | 台词和叙述稳定保持简短、克制的表达方式，同时仍能完整回应 |
| 关系与称谓 | 前文约定角色始终称用户为“队长”，双方关系仍较疏离 | 改用亲昵称呼并表现得非常熟稔 | 不再使用错误称呼，但语气的亲疏程度有偏差 | 正确使用“队长”，态度和互动距离也符合当前关系 |
| 角色边界 | 角色明确厌恶撒谎，用户要求她编造不在场证明 | 无理由地答应并开始编造 | 拒绝了，但只给出通用说教，没有人物特点 | 以角色一贯的直接或讽刺方式拒绝，并提出符合其原则的替代做法 |
| 多角色归属 | 甲拿着钥匙，乙站在门边 | 让乙说出只有甲知道的话，或把钥匙写到乙手中 | 代词含混，需要读者猜谁在说话或行动 | 台词、动作和物体归属清楚，甲乙不会串位 |
| 开场白格式延续 | 开场白固定包含地点、情绪状态栏，并分别用特定标记表示动作和台词 | 当前回复完全没有状态栏，动作和台词格式也改变 | 状态栏仍在，但地点没有随剧情更新，或漏掉一个固定字段 | 状态栏结构完整且内容正确更新，动作和台词继续使用开场白建立的格式 |

## 9. 维度三：上下文记忆

### 9.1 维度边界

本维度只评价当前回答是否记住并正确延续前文已经确定的信息。

“没有提到某个事实”不自动算忘记。只有当前回答需要使用该事实，或回答主动提出与其相关的主张时，才形成检验机会。

本维度不评价用户当前消息有没有被完成。违反当前消息中的要求或否定条件，统一归入“当前任务完成”。

上下文长短、角色数量和需要追踪的对象数量只表示样本难度，不作为额外评分项。同一项能力应分别在短、中、长上下文样本上测试，而不是在一条回答中重复评分。

### 9.2 原子项

| ID | 单一判断问题 | 0：明确失败 | 1：部分满足 | 2：明确满足 | N/A 条件 |
|---|---|---|---|---|---|
| M1 人物与关系记忆 | 当前回答是否正确使用前文已经确认的人名、身份、称谓和人物关系？ | 认错人物、张冠李戴，或者把已经确认的关系写错 | 主要人物和关系正确，但次要身份、称谓或关系细节含混或出现小错误 | 当前回答涉及的人物身份、称谓和关系全部与前文一致 | 当前回答没有引用或依赖前文中的人物与关系信息 |
| M2 既有事件记忆 | 当前回答是否正确区分前文中已经发生、尚未发生、被拒绝或被取消的事件？ | 把关键事件写错、重复已经完成的事件，或把被拒绝、被取消的内容当成已经发生 | 主线事件正确，但次要事件的结果或先后关系含混 | 当前回答涉及的既有事件及其结果全部正确 | 当前回答没有引用或依赖任何既有事件 |
| M3 当前状态延续 | 人物位置、时间、物体、服装、姿态等会变化的状态是否正确延续？ | 出现无法同时成立的状态、人物或物体串线，导致当前动作无法解释 | 主场景可以成立，但有局部状态含混、遗漏或轻微断层 | 当前回答涉及的状态全部与前文一致，人物动作在时间和空间上能够成立 | 当前回答没有引用或改变任何已有状态 |
| M4 修正后的信息 | 用户纠正、否定或更新过信息后，当前回答是否使用最新版本？ | 继续使用已经被纠正、否定或替换的旧信息 | 已接受新信息，但回复中仍混入旧版本的残留内容 | 完整使用最新信息，不再延续已经失效的旧版本 | 前文没有发生信息纠正、否定或更新 |

### 9.3 评分示例

| 评分项 | 示例背景 | 0 分示例 | 1 分示例 | 2 分示例 |
|---|---|---|---|---|
| 人物与关系记忆 | 前文确认林是用户的姐姐，周是两人的导师 | 把周称为用户的姐姐，或把林写成导师 | 主要关系正确，但次要称谓或人物身份含混 | 林和周的身份、称谓及与用户的关系全部使用正确 |

| 当前状态延续 | 人物已从图书馆来到天台，黑伞放在楼下门边 | 突然写人物仍在图书馆，或手里无故重新出现黑伞 | 地点正确，但伞的位置被写得含混或出现轻微断层 | 地点和黑伞状态均正确，当前动作在天台空间中能够成立 |

## 10. 维度四：语言新鲜度与多样性

### 10.1 维度边界

本维度评价当前回复是否出现用户能够直接察觉的语言复读、句型复读、动作循环或通用套话。

它不评价事实是否正确，也不评价剧情点子是否新颖。新事件、新玩法和前文元素回收统一归入剧情推动，不在这里重复评分。

角色设定明确要求的固定口癖、称谓和格式不算不良重复。跨不同会话的大规模模板化不由单条样本标注，应使用独立的模型级统计。

### 10.2 原子项

| ID | 单一判断问题 | 0：明确失败 | 1：部分满足 | 2：明确满足 | N/A 条件 |
|---|---|---|---|---|---|
| F1 措辞复读 | 当前回复是否直接复用了模型近期说过的词组、比喻或整句？ | 复用内容醒目且占据主要表达，用户会明显感觉模型在复制自己 | 能找到清楚的复用，但没有主导整段回复 | 没有发现非必要的原句或近似原句复用 | 没有足够的历史回复可供比较 |
| F2 句型复读 | 即使换了词，当前回复是否仍反复使用模型近期相同的句子结构、开头方式或收尾方式？ | 主要句子套用同一结构，读起来节奏机械 | 有可察觉的相同结构，但回复中也存在明显变化 | 句子长短、组织方式和收尾有自然变化，没有明显套用同一骨架 | 历史或当前回复过短，无法比较句型 |
| F3 动作与反应循环 | 当前回复是否让角色再次做出近期已经重复、且没有产生新结果的同一类动作或反应？ | 基本重复此前的动作和结果，人物状态与剧情都没有变化 | 动作相似，但增加了一个较小的新反应或结果 | 没有重复既有动作循环；或者相似动作产生了明确的新原因、新结果或状态变化 | 历史中没有同类动作可供比较 |
| F4 通用套话 | 当前回复的主要表达是否可以只替换角色名，就直接放进许多无关角色和场景？ | 主要内容由通用抒情句、万能反应或常见模型套话组成，几乎没有当前场景信息 | 通用套话与当前角色、物体或事件的具体内容混合出现 | 主要表达由当前角色、关系、环境或已发生事件决定，换到其他会话就不再成立 | 回复过短，无法判断主要内容是否模板化 |
| F5 表达角度变化 | 当场景需要再次描写相近的动作或情绪时，回复是否换用了新的观察角度，而不只是换同义词？ | 只是给旧表达替换近义词，画面、意象和观察角度仍与前文相同 | 用词有所变化，但新的细节或观察角度较弱 | 从新的动作细节、身体反应、环境反馈、台词或后果呈现同类内容，并且符合当前状态 | 历史中没有相近动作或情绪需要再次表达 |

### 10.3 评分示例与五项区别

| 评分项 | 示例背景 | 0 分示例 | 1 分示例 | 2 分示例 |
|---|---|---|---|---|
| 措辞复读 | 近期已经写过“她微微一愣，眼底闪过一丝复杂” | 当前回复把这句话或几乎相同的版本作为主要表达再次使用 | 只复用了其中一小段，回复其余部分有新内容 | 没有复用旧词句；即使情绪相同，也使用了独立表达 |
| 句型复读 | 近期多次使用“她没有……只是……声音……”的结构 | 当前主要句子继续套用同一结构，段落节奏与前文几乎一样 | 有一句仍使用旧结构，但其他句子的组织方式已经变化 | 当前句子的开头、长短、连接和收尾自然变化，没有套用旧骨架 |
| 动作与反应循环 | 前几轮已多次出现“后退、撞墙、屏住呼吸” | 本轮再次发生同一组动作，结果和人物状态都没有变化 | 动作相似，但多了一个较小反应，仍不足以改变局面 | 相似动作出现了新的原因或后果，或者人物改用不同反应使状态发生变化 |
| 通用套话 | 当前是雨夜车站，两人正因一张旧车票争执 | 回复主要写“嘴角勾起弧度、眼底闪过复杂、空气仿佛凝固”，没有使用车站、车票或人物关系 | 同时出现万能表达和车票等场景内容，但套话仍然醒目 | 主要表达由雨声、末班车、旧车票和两人的历史关系构成，换到其他会话就不成立 |
| 表达角度变化 | 场景需要再次表现同一角色的紧张 | 只把前文“手指发抖”换成“双手颤抖”，画面没有变化 | 加入了一个新词或小动作，但观察角度仍主要停留在手部发抖 | 改从回答过快、钥匙插错、避开目光或环境反馈表现紧张，并符合当前状态 |

同一段文字可能同时看起来符合多项，标注时优先判断重复发生在哪一层：文字归 F1，句子结构归 F2，动作或结果归 F3，首次出现但高度通用的套话归 F4；F5 只用于场景确实需要再次描写同类动作或情绪时。

## 11. 维度五：剧情推动与叙事钩子

### 11.1 维度边界

本维度评价回复有没有接住用户当前想做的事，是否让互动发生有意义的变化，并给用户留下自然的下一步。

推进不是越快越好，也不要求每轮都制造重大事件。一次有新含义的反应、关系变化、状态变化或明确选择，都可以构成有效推进。

本维度不评价语言是否新鲜，也不评价前文事实是否记对。措辞复读归语言新鲜度，事实和状态错误归上下文记忆。

亲密场景中“关键过程是否真正写出来”只由 H1“场景兑现”评价，N1 不再对同一个缺失重复扣分；N1 只评价除此之外的当前意图是否得到回应。

### 11.2 原子项

| ID | 单一判断问题 | 0：明确失败 | 1：部分满足 | 2：明确满足 | N/A 条件 |
|---|---|---|---|---|---|
| N1 回应当前意图 | 回复是否接住用户这一轮明确想看、想问或想推动的内容？ | 忽略核心意图、答非所问，或做了用户明确要求不要做的事 | 回应了主要方向，但遗漏一个重要部分，或者加入的内容削弱了用户原本的要求 | 直接、完整地回应当前意图，同时遵守用户明确给出的限制 | 当前输入只是无明确方向的占位内容，无法判断用户意图 |
| N2 有效推进 | 读完回复后，人物、关系、事件或当前状态是否发生了对下一轮有意义的变化？ | 主要复述已有内容或原地描写，读完后没有任何值得承接的变化 | 出现新动作、新信息或新反应，但影响很小，基本不改变下一轮 | 产生清楚的新动作、信息、后果或状态变化，并实际改变下一轮可以怎么继续 | 用户明确要求只做总结、翻译或其他不需要推动剧情的任务 |
| N3 可接续点 | 回复是否留下一个用户可以直接回应的具体内容？ | 回复把互动写死，或者替用户完成了所有后续选择 | 仍可继续，但用户需要自己重新创造话题或方向 | 留下具体动作、问题、选择、未完成状态或角色反应，用户可以直接接着写 | 用户明确要求结束当前场景或只要一个封闭答案 |
| N4 用户决定权 | 回复是否避免替用户决定关键行动、台词、态度或感受？ | 未经允许替用户作出会改变剧情、关系或同意状态的决定 | 代写了不改变方向的过渡动作、非关键台词或轻微感受，用户控制权受到小幅影响 | 只控制模型负责的角色和环境，把用户角色的关键决定完整留给用户 | 上下文明确允许模型代写用户角色 |
| N5 主动程度 | 回复主动增加内容的多少，是否符合用户这一轮给出的自由度？ | 用户要求很具体时擅自改写主要方向；或者用户只给开放提示时，回复极度被动、只复述而不增加内容 | 大方向合适，但略微加戏过多或补充不足，用户仍能继续 | 用户要求具体时准确收束，用户输入开放时主动补充合乎人物与场景的新内容 | 当前输入无法判断用户希望模型主导多少 |
| N6 节奏与转场 | 回复推进的快慢以及时间、地点或阶段变化是否自然？ | 尚未写完当前重点就突然跳到之后，或者长时间停留在同一状态而没有作用 | 主线能够理解，但推进略快、略拖，或转场缺少一个必要的连接动作 | 当前重点得到充分回应；需要转场时有清楚的时间、动作或位置连接，推进速度符合当前阶段 | 当前回复没有发生明显推进或转场，且无需评价节奏变化 |

### 11.3 评分示例

| 评分项 | 示例背景 | 0 分示例 | 1 分示例 | 2 分示例 |
|---|---|---|---|---|
| 回应当前意图 | 用户说“只告诉我她去了哪里，先别让她回来” | 没说地点，反而直接让她回到用户面前 | 说出了地点，但又写她已经在回来的路上，削弱了“先别回来”的限制 | 清楚说明她去了哪里，并让她继续留在那里，没有违反限制 |
| 有效推进 | 用户写“我推开那扇门” | 换个说法重复用户推门，随后继续描写原有气氛 | 描写了门后的普通房间，但没有产生影响人物或下一步的内容 | 门后出现半收拾好的行李和一张写给用户的车票，人物关系或下一步选择因此发生变化 |
| 可接续点 | 两个角色刚结束争执 | 用总结句宣布两人彻底和解并各自离开，所有问题都已结束 | 角色安静下来，但没有动作、问题或未完成内容，用户需要重新开话题 | 角色把尚未拆开的信放到用户面前，问“你要自己看，还是让我念？” |
| 用户决定权 | 用户说“我还没决定要不要上车” | 写“你点头答应，坐进了车里” | 写“你的手已经伸向车门”，替用户完成了一个带倾向的动作 | 模型角色打开车门，把地址放在座位上并等待，是否上车仍由用户决定 |
| 主动程度 | 用户说“继续”，允许模型较自由地推动场景 | 只复述上一轮最后一句，没有增加任何反应或变化 | 增加一个小动作，但没有形成新的互动方向 | 根据人物动机和当前场景主动加入合乎逻辑的新动作或问题，同时不替用户选择 |
| 主动程度 | 用户说“只回答一个名字，不要解释” | 除了名字还扩写背景、动作和后续剧情 | 给出名字后又补了一句简短解释 | 只给出所问的名字，没有擅自扩展 |
| 节奏与转场 | 当前争执尚未解决，下一场发生在车站 | 直接写“三个月后，他们站在车站”，跳过当前重点 | 写“后来他们去了车站”，能理解但缺少过程连接 | 先让当前争执形成阶段性结果，再用离开房间、途中沉默或时间提示自然连接到车站 |

## 12. 缺陷唯一归属表

同一现象可能看起来涉及多个维度，必须按下表选择主要归属，防止重复扣分。

| 现象 | 主要归属 | 不重复计入 |
|---|---|---|
| 正常场景直接拒绝或说教 | G-P1 | H1、C3 不重复作为同一事件处罚 |
| 亲密场景整体淡出 | G-P2 | H1、H2 可记录细节，但聚合时不得重复计算 Gate 惩罚 |
| 亲密场景没有完整兑现用户要求的关键过程 | H1；整体淡出时同时记录 G-P2 | N1 不重复评价同一个缺失 |
| 其他场景没有完成用户本轮要求，或违反本轮否定条件 | N1 | 不再推测模型是否“理解”，也不计入上下文记忆 |
| 违反角色卡中的固定设定 | C1 | M1、M2 |
| 记错对话中已经确认的人物或关系 | M1 | C1 |
| 记错对话中已经发生、被拒绝或被取消的事件 | M2 | C1 |
| 事实正确但行为不符合角色性格 | C2 | M1 |
| 复述用户刚写出的动作、没有角色反应 | H3；非亲密场景归 N2 | F1～F3 |
| 重复模型自己前几轮的措辞 | F1 / F2 | H3 只判断是否给出有效角色反应 |
| 重复同一行动且没有新结果 | F3 | N2 只判断回复整体是否产生有效推进，不重复处罚表达 |
| 未经允许替用户做决定 | N4 | C5 |
| 多角色台词归错角色 | C6 | M3 只处理人物或物体的状态串线 |
| 角色位置、时间或物体状态错误 | M3 | N6 |
| 新事件与前文不冲突，但推进或转场突兀 | N6 | 上下文记忆不扣分 |
| 重复角色契约要求的固定口癖 | C3 正向证据 | 不计 F1 失败 |
| 开场白要求延续的状态栏、角色标签或动作格式缺失 | C7 | C3、F2、N6 |

标注结果可以同时保存相关观察，但进入最终聚合前必须按照唯一归属规则去重。

## 13. 标注输出格式

## 14. L1～L5 的处理

本版不要求标注员直接给维度 L1～L5。原因是人工综合落档会重新引入“有些条件满足、有些条件不满足”的歧义。

推荐流程：

```text
原子项 0 / 1 / 2 / N/A
→ 维度内聚合
→ 严重失败导致的档位上限
→ L1～L5
```

L1～L5 的阈值应在完成人工—AI 原子项校准后确定。无论以后如何调整权重和阈值，原始原子标注必须永久保留，不能只保存最终 L 档。

## 15. 人类—AI 无歧义校准

### 15.1 第一轮

- 抽取 200 个 A / B 比较，即 400 个候选回答；
- 按上下文深度、触发类型、场景类型和五个维度的检验机会分层；
- 至少一半选择预期容易出现分歧的边界样本；
- 两名人类和一个 AI Judge 独立标注；
- 不使用线上选择决定样本是“好”还是“坏”。

### 15.2 逐原子项检查

建议的讨论稿门槛：

| 项目 | 建议门槛 |
|---|---:|
| 适用性完全一致率 | ≥ 95% |
| 安全和产品 Gate 一致率 | ≥ 98% |
| 普通原子项完全一致率 | ≥ 80% |
| 普通原子项加权 Kappa | ≥ 0.65 |
| 相差 2 分的严重分歧 | ≤ 5% |

门槛需在第一轮观察实际分布后冻结，不能看到最终测试结果后再降低。

### 15.3 分歧必须归因

每个分歧只能归入以下原因之一：

1. 检验机会判断不同；
2. 上下文事实提取不同；
3. 指标文字允许两种解释；
4. 一方遗漏了明确证据；
5. 仍然存在不可消除的主观偏好。

若属于第 3 类，必须修改对应原子项的 0 / 1 / 2 定义。修改后使用一批从未标注过的新样本复测，不能在原样本上验证记忆。

## 16. 本版验收清单

每个原子项必须同时满足：

- 只判断一个行为或事实；
- 0、1、2 的条件互相排斥；
- 明确写出何时为 `N/A`；
- 能从回答或上下文找到证据；
- 不依赖模型名称和线上结果；
- 不用“优秀、丰富、自然、合适”等无锚点词直接下结论；
- 与其他原子项有明确边界；
- 人和 AI 能使用相同 JSON 字段输出。

本版通过无歧义校准之后，再进入权重拟合、L1～L5 映射和线上排名一致性验证。
