# 公开角色评测协议审查与修正

审查日期：2026-10-18。范围：CharacterBench、CoSER/HER、MiniMax Role-Play Bench、RMTBench 的官方来源、本地补充、评分输入、完整性与缓存。检查的是本地当前代码及固定上游版本；旧服务器未连接，本次没有发付费模型请求。

## 结论

原始公开测试数据不需要重写。本地补充中，端点接入、并发、异步派生写盘、费用记录、缓存恢复属于合理的工程实现。确实存在会影响比较的评分差异：CoSER 原生与 HER 路径的角色标签、复读清理、心理可见性和 JSON 示例并不完全相同。新评分将这些显式统一；原有结果与冻结脚本保留。

不能因此认定过去的剧情质量下降全部来自评测，也不能声称修正后微调版会胜出。现有案例包含真实的场景/身份漂移和行动因果错误；本次修正消除已确认的测量混杂，未重新测量模型排名。

## 各数据集的判断

| 数据集 | 核对依据 | 判断与处理 |
|---|---|---|
| CharacterBench | 固定官方数据、actor 模板、各维评分模板和量表 | 保留。使用 GLM 替代 CharacterJudge 属于裁判替换；追加“只返回整数”是输出解析约束。不能声称复现官方榜单。3 条源输入无效继续单列，不补造问题、不计零分。 |
| CoSER/HER | 固定 CoSER 与 HER 的实际 Python 代码 | 存在不对称处理，见下表。actor 场景、角色与抽样不变；新版本统一裁判文本、严格解析与重复处理。 |
| MiniMax | 官方公开 95 个种子、六维定义、100 条新消息/三次重复/分块评分的公开方法 | 本地 simulator 与评分文案是一种可运行的近似实现，不能称精确复现。0–100 严重度档位没有人类校准证据，不应仅凭数值与官方榜单比较。本次不再凭猜测发明另一套扣分档位；修正完整性汇总并在成绩中标明未校准。 |
| RMTBench | 固定 HF 数据和论文附录 E 的模板 | 固定用户脚本、使用候选自身历史、参考答案仅给裁判是合理的。原 UPA 模板的参考答案占位符修正保留。Claude 4.5 数据、块拼接顺序、GLM 裁判是本地协议选择，不能冒充论文 Claude 3.5 完整实验；未公开 SEC/Poison 不补造。新汇总排除评分不完整的场景。 |

MiniMax 的六维包含关联概念，例如基础复读与剧情停滞，但它们来自公开分类，不能为“去重扣分”自行删掉一维。RMT 的 1–5 分与 CM/UPA 二元分仍分开保留，不合成跨 benchmark 总分。

## 已确认的问题与代码修正

| 问题 | 当前源码证据 | 新版本处理 |
|---|---|---|
| 说话者信息依赖模型自行输出 | CoSER 将 `content` 直接拼接成裁判对话，`role` 未必进入文本；HER 本地适配器另加角色名 | 对两条路径的候选与参考对话均从结构化角色字段生成前缀，包括 Environment。已有行首标签不重复添加；后文提到名字不算行首标签。 |
| 对复读做不对称清理 | CoSER `Agent.chat` 对非 GPT/Claude 模型调用 `fix_repeation`；HER 自己的 Agent 不经过该逻辑 | 新 worker 禁用这项自动清理，保留生成的重复给裁判评估。没有新增 repetition_penalty，也不额外设计复读扣分。 |
| 心理可见性影响裁判输入 | 原生 CoSER 去心理；HER 与本地 format 协议保留；部分后期实验已对两边统一 | 新配置明确 `coser_role_thoughts=include/exclude`，两候选必须一致；候选与参考都按同一规则处理。system_thinking 始终不进入评分，其他角色仍看不到私有心理，含多行心理。 |
| 原生裁判示例不是合法 JSON | CoSER 示例缺少列表闭合且含尾逗号；HER 固定源码已修正 | 两条路径共用 HER 修正后的 CoSER 裁判模板。四维语义相同；Character Fidelity 的其余差异只是空白。 |
| 角色忠实度标准仍包含字面占位符 | `dimension_criteria` 在外层替换后才插入，内部 `{major_characters}` 未展开；HER 的 `.format` 也不会递归展开参数值 | 在组装完整提示前，仅展开标准中的主角色占位符；不对角色资料或生成内容递归替换。 |
| 缺失 severity 被默认为 1 | CoSER parser 会给未返回严重度的缺陷补 1；本地适配器校验发生在补值后 | 新 parser 拒绝缺失严重度、布尔/字符串/小数、越界值、重复 JSON 键、错误维度；不默认扣分，也不默认 50/100 分。 |
| 无效内容可能成为有效评分 | 原生非空检查不能识别只剩 `角色名:` 或只剩被删掉的 system thinking | 新路径检查有效角色内容；只有空标签、角色名、分析内容的结果不进入正常评分。原始响应与失败证据保留，采用既有有限重试。 |
| seed 固定但 NSP 回退仍可能不稳定 | 从 set 转 list 后 `random.choice`，受子进程哈希随机化影响 | 仅回退候选排序后再选择。随机源、正常 NSP 输出与轮数不改。 |
| 未完成单位进入进度均分 | MiniMax 已完成的部分重复可进入种子均分；RMT 可将仅部分维度成功的场景纳入维度均分 | 原进度统计放入 `partial_scores`。`scores` 中 MiniMax 需要一个种子的所有配置重复完成；RMT 需要场景全部评分完成；缺失列表和 `score_coverage` 明列。 |

不能照搬 HER 的所有容错：固定上游 `_parse_eval_response` 在解析失败后返回 50 分，其他路径也有缺少 judge 时返回 100 分的分支。本项目不采用这些回退；失败仍是失败，不是中等或满分样本。

CoSER/HER 原评分公式保留：

`score = clip(100 - 5 × (缺陷严重度之和 - 0.3 × 角色轮数), 0, 100)`

它有轮数补偿：20 个角色轮次增加 30 分的补偿项。同一复读模式被裁判列为一条还是多条会影响总扣分，所以重复与高分可以同时出现。这是量表特性，不是算术错误。本次不擅自改成平均每轮分，也不为得到预期排名改权重；新增台词重复诊断作为并列证据。

## 使用与兼容

- `run_public_evaluation.py init` 和 `unified.example.json` 默认选择新评分版本 `20261018`。`--assessment legacy` 可以创建历史协议配置；旧配置未带 `assessment` 时不自动升级。
- 两模型共同的 `--coser-role-thoughts` 必须一致。默认 `include` 与 HER 的保留角色心理方式一致；要观察可见对话效果，可两边同时使用 `exclude`，保存为另一个实验。
- actor 提示、温度、输出上限、模型权重、并发和写盘架构不因评分修正自动变动。CoSER 原生约 60 词与 HER 约 200 词提示、自身历史处理仍有差异；若要隔离训练收益，还需同提示/同历史对照。
- 新版本必须创建新结果目录；不能把新评分塞回旧运行。已经准备的旧 HER 任务需使用它记录的代码版本恢复；不要修改 manifest 绕过哈希。原始日志、成功缓存和旧结果不删除。
- 新原始响应依旧先进入持久日志；新格式错误不会进入 worker 的成功缓存。重复调用已成功请求仍重放缓存；超时计费不明请求的隔离策略不变。
- MiniMax 小样本只选一条 session 时，可显式用 `repeats=1` 做烟测；若只选择了种子的一部分重复，调用可以全部完成，但 `score_coverage.complete` 为 false，不作为完整种子成绩。

## 验证与剩余不确定性

回归测试直接从固定上游加载 `gca_judging`，在 native、format、HER 三条路径及两种心理可见性下执行相同对话，要求实际裁判请求完全一致，并验证原公式。另覆盖非法评分、真实本地 HTTP 代理失败重试/缓存重放、源文件未修改、MiniMax/RMT 完整性、报告一致性、并发限额与异步恢复。

验证记录：九个相关测试模块合计 71 项通过；随后针对审查工具、报告集成和配置的 34 项检查通过。最后增加了实际执行原生 `Agent.chat` 的复读保留回归。固定上游测试会输出已有的文件未显式关闭 ResourceWarning，不影响断言结果。

MiniMax 尚未做人类校准，也没有取得未公开官方 simulator/judge 文案。代码正确性测试不能证明 GLM 的语义判断可靠或新分数更接近人类。本次也未重新生成或重新评分全量模型，旧成绩仍按旧协议解释。后续需要验证评分质量时，应固定已有轨迹与人工标注样本，再检查同一裁判对复读、场景跳跃、角色混淆的识别率和重复评分波动；不要先改提示追求某个模型分数上涨。
