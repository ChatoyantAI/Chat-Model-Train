# Reduce evaluation storage waits

The original runner used lightweight temporary-file replacement for ordinary
JSON checkpoints. Recovery added synchronous file and directory fsync to each
checkpoint and put all transport records in large flat directories. On this
GeeseFS volume, directory operations then dominated request turnaround.

The recovery launcher now uses four background writers, bounded to 256 pending
paths. Updates to the same progress/checkpoint path are coalesced; distinct
attempt records are preserved. Reads see pending updates. Judging waits for its
trajectory, aggregation waits for that suite's writes, and normal exit flushes
the queue. Publication errors stop new broker dispatch. `--sync-checkpoints`
retains the synchronous path for rollback.

Paid request intent, original response, replay response, and cost ledger remain
synchronous and durable before reply. New transport records use hash-prefix
subdirectories under `operations-v2` and `responses-v2`. Old directories remain
readable and unchanged. Startup probes only the needed legacy cache key, rather
than listing the entire legacy response directory. Scope, fingerprints, frozen
prompts, sampling, scoring parsers, and actual-cost accounting are unchanged.
This is not an in-memory-only cache: a successful upstream response can be
replayed if its ordinary checkpoint was not published before an interruption.

Detached launches use a fresh interpreter before writer threads start, with a
unique log outside the frozen launcher's stale-state log rotation. A loopback
`POST /control/drain` closes broker admission while existing calls finish; this
supports subsequent controlled maintenance without changing model identity.

## Measured storage behavior

On the same remote host, a 1 KB write into the old flat response directory took
54.20 seconds in open/rename/directory-sync operations alone (24.43 + 13.73 +
16.05 seconds); file fsync added approximately 0.10 seconds. An isolated new
directory did not show that delay.

Six synthetic samples of the new layout measured a median 0.640 seconds for
three critical writes and 0.00142 seconds to enqueue 22 ordinary updates.
All samples, including final flush, took 4.91 seconds. This was an I/O test,
not a whole-benchmark speedup claim, and made zero model requests. Evidence:
`outputs/full-public-v1/diagnostics/async-io-1789615754/measurement.json`.

## Validation and deployment

59 local tests passed, including delayed/coalesced writes, bounded backpressure,
write failure handling, journal replay, and a complete offline MiniMax run.
That run retained identical scores and costs and resumed with zero new calls.
41 transport/writer tests also passed on the remote host; the frozen-source,
manifest, and model-identity preflight passed.

Following explicit user confirmation, supervisor 90922 was replaced by 92951
on 2026-09-17. Only the evaluation supervisor was stopped; the load balancer and
vLLM engines were kept running. Before replacement, old ledger hashes were
recorded and unaccounted request records reconciled into one new ledger segment.
27 response bodies were recovered; 16 requests had no recoverable response
(14 remote, 2 local). Those uncertain requests are skipped instead of resent.
All 43 interrupted operation keys are quarantined at dispatch; the 27 recovered
valid responses remain available to replay before dispatch. Invalid responses
remain evidence and are not converted into valid benchmark scores.

Recovered provider-reported charges total $0.008709525. A further $1.40 is an
unknown-cost reserve, **not confirmed spending**. Existing reserves and the
$100 guard were not raised or cleared. Old logs, status, and locks are archived
under `outputs/full-public-v1/interruption-20260917T034053Z-async-io/`, including
`reconciliation.json` and `replacement.json`. Successful caches were not deleted
or rewritten. New process log: `supervisor-run-20260917T034053Z.log`.

The replacement uses the same remote/local concurrency caps (64/16), public
workers 28 per suite, and `--rmt-judge-existing-only` to skip the previously
accepted missing generation tail. GLM 5.1 remains paused. Partial coverage and
quarantined requests must remain visible in final per-benchmark reporting.

At 03:43:50 UTC, the replacement had completed 31 GLM Flash and 12 local Gemma
requests, with no new broker errors or persistence failures. Median broker
turnaround in this small initial sample was 24.86 seconds for GLM Flash and
32.10 seconds for Gemma; only two ordinary writes were pending. The earlier
roughly 74-second GLM median and this initial sample are not a controlled
benchmark comparison (the workload includes both judging and simulation).
The remaining guard allowance was about $2.38 after actual reported cost
$38.22 and $59.40 in unknown-cost reserves. In-flight reservation therefore
also limits effective API concurrency below the configured cap of 64.

## User-authorized removal of the spending guard

The user subsequently explicitly requested disabling the budget protection
while retaining accounting. `--no-budget-guard` disables both total-spend
rejection and the per-in-flight $0.10 admission reservation. It does not change
the concurrency gates (remote 64, local 16), paid-response persistence, retry
rules, or historical cost/unknown-reserve records. Status now explicitly reports
`budget_guard_enabled: false` and a null spending limit; unknown reserves remain
accounting information, not confirmed spend and not an admission cap.

A dedicated offline test verifies calls can proceed above the former limit,
actual costs still reach the ledger, unknown reserves are retained, and the
remote concurrency gate remains bounded. All 39 recovery tests passed. The
frozen-source preflight also passed on the host. Deployment uses the loopback
drain endpoint and waits for both active calls and pending writes to reach zero
before replacing the supervisor; no new interruption quarantine is necessary.

At 03:52:26 UTC, the drained supervisor was replaced by PID 93834 using
`async-io-no-budget-20260917`. Its live broker and supervisor status both confirm
the guard is disabled. The initial accounting totals ($38.360595112 reported,
$59.40 unknown reserve) were retained. Maintenance evidence is in
`interruption-20260917T035226Z-no-budget`; the new log is
`supervisor-run-20260917T035226Z-no-budget.log`.
