# 线上 ELO 投票的最终计算与数据冻结方案

## 1. 决策摘要

本次 campaign 有11个聚合去重后的模型，覆盖全部 `C(11, 2) = 55` 个无序模型对。每个用户最多贡献一张有效票，每张票权重相同。

最终计算规则：

1. 只保留已经完成选择的有效记录；
2. 根据用户选择识别胜方模型和负方模型；
3. 随即丢弃左右位置，两个展示方向完全合并；
4. 对全部胜负票一次性拟合标准 Bradley–Terry 模型；
5. 将内部相对能力转换成均值为1000的 Elo 风格展示分数；
6. 按完整精度分数排序，并用分层 bootstrap 报告95%分数和排名区间。

左右信息只用于上线期间检查分配是否均衡，不进入最终排名算法。

## 2. 从投票到胜负矩阵

进入计算前，每条记录必须归一化为：

```text
user_id, winner_model, loser_model
```

例如以下两种展示都记为同一个结果：

```text
A在左、B在右、用户选择A  -> A胜B
B在左、A在右、用户选择A  -> A胜B
```

定义：

```text
W[i][j] = 模型i战胜模型j的有效票数
```

对于任意模型对 `i, j`：

```text
总票数 N[i][j] = W[i][j] + W[j][i]
原始胜率       = W[i][j] / N[i][j]
```

原始两两胜负表必须作为正式结果的一部分保留，以便任何人从票数复核模型分数。

## 3. 初始化

内部为每个模型设置一个对数能力 `theta[i]`：

```text
theta[0] = theta[1] = ... = theta[10] = 0
```

初始化为0表示所有模型初始完全相同，任意一组预测都是50:50。这里没有来自旧 ELO、模型价格、模型发布时间或离线 Evaluation 的初始分。

`theta` 只是批量优化的内部参数，不会在投票到达时逐条更新。

## 4. 胜率模型

模型 `i` 战胜模型 `j` 的概率为：

$$
P(i > j)=\frac{1}{1+e^{-(\theta_i-\theta_j)}}
$$

模型只使用 `theta[i] - theta[j]`，不存在左侧或右侧参数。

## 5. 联合拟合全部55个模型对

对每组模型，负对数似然为：

$$
L_{ij}=-W_{ij}\log P_{ij}-W_{ji}\log(1-P_{ij})
$$

全部数据的目标函数为：

$$
L=\sum_{i<j}L_{ij}
$$

计算程序寻找使 `L` 最小的一组 `theta`。这会同时考虑：

- 51:49只是很小的能力差；
- 80:20代表更大的能力差；
- A胜B、B胜C、C胜A等循环关系；
- 各模型对票量存在的小幅差异。

每张有效用户投票权重为1，不按模型对、左右、时间或用户属性增加权重。

实现使用带回溯线搜索的 Newton 法：

```text
初始化所有theta为0
固定最后一个theta为0，解除整体平移的不唯一性
重复：
    计算全部55组数据的损失、梯度和Hessian
    解 Newton 更新方向
    回溯选择能降低损失的步长
    更新theta
直到最大梯度 <= 1e-9 或达到迭代上限
最后将所有theta重新居中，使平均theta为0
```

固定某个参数只是计算技巧，最终重新居中后不会偏向该模型。程序不加入统计先验或位置修正；如果胜负图不满足有限极大似然条件，会显式失败，而不是静默生成任意分数。

## 6. 从 theta 转换成展示分数

拟合结束后：

$$
Score_i=1000+\frac{400}{\ln(10)}\theta_i
$$

其中：

```text
400 / ln(10) = 173.717792761...
```

含义：

- `theta` 是实际拟合的内部相对能力；
- `173.7178` 只是把自然对数单位换成传统 Elo 单位；
- `1000` 只是展示中心，使本次11个模型的平均分为1000；
- 只有分差有意义，绝对分数没有独立含义。

换算后，两个模型的预测公式等价于：

$$
P(A > B)=\frac{1}{1+10^{(Score_B-Score_A)/400}}
$$

例如一个模型对的票数单独为120:80，则胜率为60%，赔率为1.5，分差约为：

$$
400\log_{10}(1.5)=70.44
$$

正式计算会联合考虑所有模型对，所以最终分差不一定恰好等于任意单组票数换算值。

## 7. 排名与不确定性

正式点排名按照未四舍五入的 `Score` 从高到低排列。展示时可以保留一位小数，但不能用四舍五入后的数值重新排序。

置信区间使用固定模型对票量的分层非参数 bootstrap：

```text
重复2000次：
    在每个无序模型对内部有放回抽取相同数量的投票
    重新拟合全部模型分数
    记录每个模型的分数和排名
```

最终报告每个模型的：

- 点估计分数与完整排名；
- 2.5%～97.5%分位的分数区间；
- 2.5%～97.5%分位的排名区间；
- 总胜负、原始胜率和参赛票数。

还可以用同一批 bootstrap 样本计算某个排名结论的支持率。例如，“A高于B的支持率”是重复拟合中 `Score_A > Score_B` 的比例，“A排第一的支持率”是A取得第1名的比例。这些数值是 bootstrap 稳定性指标，不是贝叶斯后验概率。

业务如果需要输出严格的1～11名，可以使用点估计排序；解读相邻模型差异时必须同时查看区间和顺序支持率，不能把区间大量重叠解释成确定的质量差异。完整顺序的支持率通常会远低于第一名或梯队边界的支持率，这是多个接近名次的不确定性累积造成的。

## 8. 停止 ELO 后的数据冻结

生产 campaign 停止后应按以下顺序执行：

1. 记录明确的 campaign ID 和北京时间停止时刻；
2. 使用只读生产数据库账号查询停止时刻之前的数据；
3. 只保留 `selected` 且存在明确选择的记录；
4. 验证每个用户最多一张有效票；
5. 根据被选中的消息解析 `winner_model` 和 `loser_model`；
6. 导出为 [标准 CSV 契约](../data/elo_ranking/vote_schema.json)；
7. 将原始导出保存在 Git 忽略的 `data/raw/` 或外部不可变存储；
8. 记录文件 SHA-256、记录数、时间范围、11个模型和55组票量；
9. 运行排名工具并保存 `ranking.csv`、`pairwise.csv` 和 `summary.json`；
10. 对照数据库聚合数复核总票数、每组票数和每个模型胜负数。

正式 SQL 应在停止后根据当时生产 schema 编写和复核，不在代码中保存数据库地址、SSH 信息或凭据。标准化导出至少包含：

```text
comparison_id
user_id
campaign_id
selected_at
winner_model
loser_model
```

计算工具故意不接受 `left_model`、`right_model` 或 `selected_side` 作为评分变量，确保左右不会意外进入算法。

## 9. 数据验收门槛

正式出分前必须通过：

- campaign ID 唯一且与冻结记录一致；
- 恰好11个聚合模型；
- 55个无序模型对均存在有效票；
- 每个用户最多一票；
- 没有自身比较、空模型ID或无法解析的胜方；
- CSV行数等于所有 `W[i][j]` 之和；
- 每个模型的胜票加负票等于它的总参赛票；
- 胜负有向图强连通，标准 Bradley–Terry 极大似然存在有限解；
- 最终11个展示分数的平均值为1000；
- 相同输入、代码版本和随机种子可复现相同结果。

## 10. 不采用的做法

- 不按照投票时间逐条更新传统 Elo；
- 不使用旧 ELO 分数作为初值或先验；
- 不加入左右位置参数；
- 不把左侧整体选择率用于修正任何模型；
- 不只按照“赢过几个对手”忽略胜负票差；
- 不把不同 campaign 的1000分制绝对分数直接横向比较。

## 11. 解释边界与已知限制

- Bradley–Terry 将所有上下文、角色和用户偏好压缩成一个一维相对能力，可能掩盖模型之间的循环胜负和分场景优势；
- 一张票代表一次真实线上偏好，不代表候选回答存在客观且唯一的正确标签；
- 不纳入左右位置的前提是模型在左右两侧获得近似均等的曝光机会，位置均衡必须在数据验收阶段单独验证；
- 没有选择、生成失败或候选输出无效的记录不进入评分，因此结果描述的是成功生成且完成选择的样本；
- 95%区间反映当前采样和模型假设下的统计不确定性，不覆盖线上配置变化、用户选择机制等系统误差；
- 1000分是 campaign 内部展示中心。模型集合、流量、触发条件或时间窗口变化后，应创建新的 campaign 并重新计算，不能直接比较两个 campaign 的绝对分数。
