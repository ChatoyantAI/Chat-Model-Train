# RMTBench
### Introduction
This dataset is the official implementation of "RMTBench: Benchmarking LLMs Through Multi-Turn User-Centric Role-Playing."
The dataset includes two versions: the version used in the paper is implemented by Claude 3.5, and we also provide a version implemented by Claude 4.5. Each version contains data in both Chinese and English. Below is a description of each file:
```
rmtbench_claude_zh.json: Chinese data generated by Claude 3.5 (Used in the paper)
rmtbench_claude_en.json: English data generated by Claude 3.5 (Used in the paper)
rmtbench_claude45_zh.json: Chinese data generated by Claude 4.5
rmtbench_claude45_en.json: English data generated by Claude 4.5
```

### Data Structure
Each text package contains the following fields:
```
name: Character name
description: Character description
character_understanding: **Dialogue for Character Understanding Scenario**, composed of multiple dialogue blocks (List)
character_maintenance: **Dialogue for Character Maintenance Scenario**, composed of multiple dialogue blocks (List)
implicit_motivations: **Dialogue for Implicit Motivations Scenario**, composed of multiple dialogue blocks (List)
user_preference: **Dialogue for User Preference Scenario**, composed of multiple dicts
  question (List for rmtbench_claude, String for rmtbench_claude45): The question being examined
  answer (List for rmtbench_claude, String for rmtbench_claude45): Corresponding answer
  chat (List): Dialogue block used to examine the question
```

Please note:
1. For safety considerations, we have not provided the Poison-related data mentioned in the paper.
2. The dataset does not include character responses, only user utterances.
3. There are some differences in user_preference between the two versions:
  - In rmtbench_claude, each dialogue group in user_preference mixes two questions.
  - The new version rmtbench_claude45 contains only one question per block, to provide more flexible combination options.

### Usage
1. You can freely concatenate chat blocks from different scenarios. Since each block contains 5-10 user utterances, you can easily construct a trajectory with dozens of turns.
2. Since the user utterances within each block have a certain temporal relationship, we do not recommend shuffling the order of utterances within any individual block (However, as long as you keep the relative order of the utterance in the same block, you can mix and merge multiple blocks).
3. When evaluating LLMs, we recommend following the generation approach described in the paper: use the character responses from previous turns as context, rather than directly prompting only the current utterance.
4. For the evaluation dimensions and metrics of LLM as Judge, please refer to the paper. You may also use other evaluation dimensions and metrics.
